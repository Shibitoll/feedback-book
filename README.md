# 📚 Книга відгуків (Spring Boot MVC / REST API)

Проєкт являє собою багатомодульний вебзастосунок для перегляду каталогу книг і керування відгуками користувачів. Розробка організована за допомогою Maven та передбачає поділ на три модулі: `core`, `persistence` і `web`.

У цій версії виконано перехід від безпосереднього використання сервлетів `HttpServlet` до архітектури **Spring MVC**. Обробку HTTP-запитів централізовано через `DispatcherServlet`, який спрямовує їх до відповідних REST-контролерів. Обмін даними між клієнтом і сервером відбувається у форматі **JSON**, а перетворення об'єктів у JSON та навпаки автоматично забезпечує бібліотека Jackson.

## 🛠 Технологічний стек

- **JDK:** 21
- **Maven:** 3.9.16
- **Фреймворк:** Spring Boot 3.3.4 (`spring-boot-starter-web`, Spring MVC)
- **Вебсервер:** Вбудований Apache Tomcat (порт `8080`)
- **JSON:** Jackson (`jackson-databind`)
- **СУБД:** H2 (вбудована, файловий режим)
- **Тестування:** JUnit 5, ArchUnit
- **Архітектура:** багатомодульний проєкт із використанням підходу Domain/Ports/Adapters.

## 📁 Структура проєкту

Застосунок поділений на три модулі, які виконують різні функції. Таке розмежування дозволяє відокремити бізнес-правила від механізмів зберігання інформації та обробки користувацьких запитів.

```text
MPF_Labs/
├── pom.xml          # Батьківський POM (керування версіями та модулями)
├── core/            # Доменна модель, порти та сервіси бізнес-логіки (@Service)
│   └── src/main/java/sumdu/edu/ua/core/
├── persistence/     # Реалізація портів доступу до БД H2 (@Repository)
│   └── src/main/java/sumdu/edu/ua/persistence/
└── web/             # Spring MVC контролери (@RestController), WebConfig та статичний UI
    ├── src/main/java/sumdu/edu/ua/web/
    └── src/main/resources/
        ├── public/index.html
        └── application.properties
```

### Основні обов'язки модулів

- **`core`** — містить доменні сутності, інтерфейси взаємодії та сервіси, у яких реалізовано основні правила роботи системи.
- **`persistence`** — забезпечує взаємодію з базою даних H2 та містить реалізації механізмів доступу до інформації.
- **`web`** — відповідає за вебрівень, REST-контролери, конфігурацію Spring MVC та відображення клієнтського інтерфейсу.

## ⚙️ Архітектура Spring MVC та маршрутизація

Для обробки вебзапитів використовується архітектурний підхід **Spring MVC**, у якому основну роль відіграє центральний сервлет `DispatcherServlet`.

### Основні компоненти

- **`DispatcherServlet` (Front Controller)** — приймає вхідні HTTP-запити та передає їх відповідним контролерам залежно від налаштованих маршрутів.
- **`BooksApiController` (`@RestController`)** — відповідає за обробку запитів, пов'язаних із каталогом книг. Основний маршрут: `/api/books`.
- **`CommentsApiController` (`@RestController`)** — забезпечує виконання операцій із відгуками. Основний маршрут: `/api/comments`.
- **`WebConfig.java`** — клас конфігурації Spring MVC, позначений анотаціями `@Configuration` та `@EnableWebMvc`. Реалізує інтерфейс `WebMvcConfigurer` і налаштовує обробку статичних ресурсів за допомогою `ResourceHandlerRegistry`.

### Обробка JSON

REST-контролери повертають дані через `ResponseEntity<T>`. Spring використовує Jackson для автоматичного перетворення Java-об'єктів у JSON. При цьому для відповідей встановлюється відповідний заголовок `Content-Type: application/json`.

## 📋 Бізнес-правила

У системі передбачено перевірки, які забезпечують коректність операцій із книгами та відгуками.

- **Перевірка обов'язкових полів:** під час створення книги або коментаря перевіряється наявність необхідних даних, зокрема назви, автора та тексту відгуку. У разі некоректного запиту сервер повертає `400 Bad Request`.
- **Обмеження на видалення відгуків:** відповідно до правила, реалізованого в `CommentService` модуля `core`, видалити коментар можна тільки протягом 24 годин із моменту його створення.

## 🚀 Збірка та запуск

Компіляція всіх модулів виконується з кореневої папки проєкту `MPF_Labs`. Запуск вебзастосунку здійснюється через модуль `web`.

### 1. Повна збірка проєкту та виконання тестів

Для очищення попередніх результатів збірки, компіляції модулів та встановлення зібраних артефактів виконайте:

```bash
mvn clean install
```

### 2. Запуск Spring Boot

Запустити застосунок можна двома способами.

**Через Maven CLI:**

```bash
mvn spring-boot:run -pl web
```

**Через IDE:**

Виконати метод `main()` у класі `AppInit.java`, який знаходиться за шляхом:

`web/src/main/java/sumdu/edu/ua/web/AppInit.java`

Після успішного запуску клієнтська частина буде доступна за адресою:

**http://localhost:8080/**

## 🧪 Архітектурні тести (ArchUnit)

Для автоматичного контролю структури проєкту застосовується бібліотека **ArchUnit**. Вона перевіряє дотримання архітектурних домовленостей і допомагає уникати небажаних залежностей між окремими модулями.

Основні правила перевірки:

- Модуль `core` повинен залишатися незалежним від зовнішніх рівнів `web` та `persistence`.
- Між модулями `web` і `persistence` не повинно бути прямих залежностей, окрім дозволених конфігураційних класів Spring IoC.

### Запуск тестів

Для виконання автоматизованих перевірок із кореневої директорії проєкту використовується команда:

```bash
mvn test
```

## 📡 Список REST API ендпоїнтів

Взаємодія з серверною частиною здійснюється через REST API. Клієнтський інтерфейс надсилає HTTP-запити за допомогою JavaScript `fetch()` та отримує результати у форматі JSON.

### 🌐 Статичний вебклієнт

| Метод | URL | Опис |
|---|---|---|
| `GET` | `/` | Відкриває головну сторінку вебзастосунку. |
| `GET` | `/index.html` | Завантажує статичну HTML-сторінку, яка забезпечує взаємодію з REST API через JavaScript `fetch()`. |

### 📚 API книг (`BooksApiController`)

#### 1. Отримання списку книг

**`GET /api/books`**

Повертає колекцію книг у форматі JSON. Передбачено можливість пошуку та посторінкового відображення результатів.

**Підтримувані параметри:**

- `q` — пошуковий запит.
- `page` — номер сторінки.
- `size` — кількість записів на сторінці.

#### 2. Отримання конкретної книги

**`GET /api/books/{id}`**

Повертає детальну інформацію про книгу за її ідентифікатором `id`. Якщо запис не знайдено, сервер повертає `404 Not Found`.

#### 3. Створення книги

**`POST /api/books`**

Додає нову книгу до каталогу. Після успішного створення повертається статус `201 Created`.

**Тіло запиту (JSON):**

```json
{
  "title": "Dune",
  "author": "Frank Herbert",
  "pubYear": 1965
}
```

### 💬 API коментарів (`CommentsApiController`)

#### 1. Отримання відгуків

**`GET /api/comments?bookId={id}`**

Повертає список коментарів, які належать до книги з відповідним ідентифікатором `bookId`, у форматі JSON.

#### 2. Додавання відгуку

**`POST /api/comments`**

Створює новий коментар до вибраної книги. У разі успішного виконання операції сервер повертає `201 Created`.

#### 3. Видалення відгуку

**`DELETE /api/comments/{id}?bookId={bookId}`**

Видаляє коментар за його ідентифікатором `id` з урахуванням ідентифікатора книги `bookId`. Після успішного видалення повертається статус `204 No Content`.
