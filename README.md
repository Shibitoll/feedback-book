# 📚 Книга відгуків (Javalin REST API)

Проєкт являє собою багатомодульний вебдодаток для перегляду каталогу книг та роботи з відгуками. Він побудований на основі **Maven** і поділений на три модулі: `core`, `persistence` та `web`.

У поточній версії для обробки запитів замість Jakarta Servlet API та JSP використовується мікрофреймворк **Javalin**. Взаємодія між клієнтською та серверною частинами відбувається через REST API з обміном даними у форматі JSON. Клієнтська частина реалізована за допомогою HTML і JavaScript. Для зберігання інформації використовується вбудована база даних H2 через JDBC.

## 🛠 Технологічний стек

- **JDK:** 21
- **Maven:** 3.9.16
- **Вебфреймворк:** Javalin 6.2.0 (використовує вбудований Jetty)
- **Обробка JSON:** Jackson (`jackson-databind`, `jackson-datatype-jsr310`)
- **СУБД:** H2 (вбудована)
- **Логування:** SLF4J + Logback
- **Тестування:** JUnit 5, ArchUnit
- **Архітектура:** багатомодульна організація з використанням підходу Domain/Ports/Adapters.

## 📁 Структура проєкту

Код організовано у три окремі модулі, кожен з яких виконує власні завдання. Такий поділ дає змогу відокремити бізнес-логіку від роботи з даними та обробки HTTP-запитів.

```text
MPF_Labs/
├── pom.xml       # Основна конфігурація Maven та підключення модулів
├── core/         # Доменні моделі, бізнес-логіка та порти
│   └── src/main/java/sumdu/edu/ua/core/
├── persistence/  # Робота з H2 та реалізація механізмів доступу до даних
│   └── src/main/java/sumdu/edu/ua/persistence/
└── web/          # REST-контролери Javalin, DTO, Middleware, конфігурація та клієнтська частина
    └── src/main/java/sumdu/edu/ua/web/
```

### Призначення модулів

- **`core`** — відповідає за предметну область, містить доменні сутності, бізнес-правила та порти для взаємодії з іншими компонентами.
- **`persistence`** — забезпечує роботу з базою даних H2 та реалізує операції зі збереження й отримання інформації.
- **`web`** — реалізує REST API за допомогою Javalin, обробляє запити, працює з DTO та забезпечує взаємодію із клієнтською частиною.

## 📋 Бізнес-правила

### Обмеження на видалення відгуків

Видалити відгук можна лише протягом **24 годин із моменту його створення**. Перевірка цього обмеження виконується в класі `CommentService` модуля `core`, що дозволяє зберігати відповідне правило на рівні бізнес-логіки.

## 🚀 Збірка та запуск

Для роботи з проєктом команди потрібно виконувати з кореневої директорії `MPF_Labs`.

### 1. Збірка проєкту та запуск тестів

Для очищення попередніх результатів збірки, компіляції модулів і виконання тестів використовується команда:

```bash
mvn clean install
```

### 2. Запуск вебдодатка

Для запуску застосунку на основі Javalin через `exec-maven-plugin` виконайте:

```bash
mvn -pl web exec:java
```

Після успішного запуску клієнтська частина буде доступна за адресою:

**http://localhost:8080/**

## 🧪 Архітектурні тести (ArchUnit)

Для контролю дотримання архітектури використовується бібліотека **ArchUnit**. За допомогою автоматизованих тестів перевіряється правильність організації модулів і відсутність небажаних залежностей між ними.

У проєкті встановлено такі обмеження:

- Модуль `web` не повинен безпосередньо залежати від `persistence`, за винятком конфігураційного класу `Beans`.
- Модуль `core` має залишатися незалежним від `web` та `persistence`.
- Модуль `persistence` не повинен використовувати компоненти з `web`.

### Запуск архітектурних тестів

Перевірити виконання всіх тестів можна командою з кореневої директорії:

```bash
mvn test
```

## 📝 Логування та обробка помилок

Для реєстрації подій і контролю роботи застосунку використовуються **SLF4J та Logback**. У вебмодулі також передбачено Middleware, яке дає змогу відстежувати HTTP-запити та отримані відповіді.

### Middleware

Механізми `app.before` та `app.after` використовуються для автоматичного запису інформації про вхідні запити й статуси відповідей у консоль.

### Рівні логування

- **`INFO`** — використовується для запису інформації про отримані HTTP-запити (`-> Request`), відповіді сервера (`<- Response`), а також успішне створення та видалення відгуків.
- **`WARN`** — фіксує попередження, пов'язані з некоректними клієнтськими запитами та помилками зі статусами `4xx`.
- **`ERROR`** — застосовується для реєстрації внутрішніх помилок сервера зі статусами `5xx`. Записи містять повний стек викликів (`stack trace`).

### Обробка винятків

Для централізованої обробки помилок використовується механізм `app.exception`. Він перехоплює винятки, що виникають під час виконання запитів, і повертає клієнту повідомлення у форматі JSON:

```json
{
  "error": "Internal server error",
  "message": "деталі винятку"
}
```

## 🗄 База даних

Для зберігання інформації про книги та пов'язані з ними відгуки застосовується **H2 Database** у файловому режимі.

- **СУБД:** H2.
- **URL підключення:** `jdbc:h2:file:./data/guest;AUTO_SERVER=TRUE`
- **Розташування файлу:** `./data/guest.mv.db`

База даних створюється автоматично під час першого запуску застосунку, якщо відповідний файл ще відсутній.

## 📡 Список REST API ендпоїнтів

### 🌐 Клієнтська частина

| Метод | URL | Призначення |
|---|---|---|
| `GET` | `/` | Перенаправляє користувача на статичну сторінку `/index.html`, де відображається каталог книг. Дані завантажуються за допомогою JavaScript `fetch()`. |

### 📚 API книг (`BooksController`)

#### 1. Отримання списку книг

**`GET /api/books`**

Повертає перелік книг у форматі JSON. Передбачено пошук за назвою або автором, а також розбиття результатів на сторінки.

**Параметри запиту:**

- `page` — номер сторінки.
- `size` — кількість книг на одній сторінці.
- `q` — текст для пошуку за назвою або автором.

**Приклад запиту:**

```http
GET /api/books?q=java&page=0&size=10
```

#### 2. Отримання інформації про книгу

**`GET /api/books/{id}`**

Повертає дані конкретної книги у форматі JSON за її ідентифікатором.

**Приклад запиту:**

```http
GET /api/books/1
```

#### 3. Додавання книги

**`POST /api/books`**

Створює новий запис у каталозі книг на основі переданих JSON-даних.

**Тіло запиту:**

```json
{
  "title": "Захар Беркут",
  "author": "Іван Франко",
  "pubYear": 1883
}
```

### 💬 API коментарів (`CommentsController`)

#### 1. Отримання коментарів

**`GET /api/comments?bookId={id}`**

Повертає список відгуків, пов'язаних із конкретною книгою. Дані передаються у форматі JSON із підтримкою значень дати й часу типу `Instant`.

**Приклад запиту:**

```http
GET /api/comments?bookId=1
```

#### 2. Додавання коментаря

**`POST /api/comments`**

Створює новий відгук для вибраної книги. Після успішного додавання повертається статус `201 Created`.

**Тіло запиту:**

```json
{
  "bookId": 1,
  "author": "Бондарєв Іван",
  "text": "Цікава книга."
}
```

#### 3. Видалення коментаря

**`DELETE /api/comments/{id}?bookId={bookId}`**

Видаляє відгук за його ідентифікатором. Перед виконанням операції перевіряється дотримання бізнес-правила, яке дозволяє видалення лише протягом 24 годин після створення коментаря.
